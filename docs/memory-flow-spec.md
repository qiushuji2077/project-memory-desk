# 记忆流规范 v1（Memory Flow Spec v1）

记忆流规范 v1 统一了所有录入入口（手动 / 对话 / 录音 / 文件）的记忆词表，让"输入端"与"最终记忆输出端"对齐。它的目标只有一个：**只记"不可再生"的东西**，把噪音挡在记忆流之外。

## 核心原则：只记不可再生

项目真正难的不是保存更多资料，而是随时知道当前采用什么。因此：

- 能直接从**已交付文件**里读到的内容，一律不记——尤其是"我把 X 改成了 Y"这类修改动作，改完的结果已经在文件里。
- 修改只沉淀成两样东西：改完形成的**新口径（定）**，和这么改的**理由（判断）**。
- 两极框架：**判断 = 压缩极**（为什么这么定），**原话 = 保真极**（不可改写的原始表述），中间"描述改了什么"基本是可再生噪音。

## 封闭词表 4 + 1

每条记忆一行，统一格式 `类型【来源】：内容`（来源可省）。

| 类型 | 含义 | 来源标注示例 | 三流归类 |
| --- | --- | --- | --- |
| **定** | 已拍板、后续默认沿用的结论，或贯穿全篇的口径 | `【对方确认】` `【我方·未审定】` `【沿用原稿】` | 已确认 |
| **判断** | 影响后续取舍的专业判断，**必须带一句"因为……"** | `【我方·未审定】` | 判断 |
| **原话** | 不可改写的原始表述，加引号 | `【负责人】` `【受访者】` `【文件】` | 已确认 |
| **待确认** | 尚未拍板、会卡住后续的问题 | — | 当前 |
| **废弃** | 被推翻、要防止以后又被捡回来的旧结论，附一句为何废弃 | — | 仅在"全部"可见，不进入最终记忆 |

来源折进正文：`定【对方确认】：……` 展示为"（对方确认）……"，种类判定不变，老记忆（无【来源】）继续兼容。

## 两步噪音自检

落笔前，对每条做两步自检：

1. **能不能从已交付文件读到？** 能 → 不写（除非它是贯穿全篇的口径＝定，或某个决定背后的理由＝判断）。
2. **以后影不影响命名、结构、关键产出、评审、实施路径、交付节奏？** 不会 → 删。

一句话：宁可少，不制造噪音。

## 四个入口，同一套词，侧重不同

| 入口 | 主要产出 | 特别规矩 |
| --- | --- | --- |
| 手动输入 | 定 + 判断 | 自由录入，但限这 5 个前缀 |
| 从对话提取 | 定 + 判断 | **明令禁止记修改动作**，几乎只产出定和判断 |
| 从录音提取 | 原话 + 待确认 + 定 | 首要任务是抢救原话（录音过时即失，逐字保留） |
| 从文件提取 | 定 + 原话 + 待确认 | 同一内容多版本只留最新、最正式、最完整 |

## 最终记忆：每次全量重建

最终记忆只是记忆流的**压缩缓存**，可随时丢弃重算；记忆流是只增不删的底稿。

- **默认全量**：每次都喂完整记忆流，从底稿重新整理，不沿用、不信任之前生成过的任何最终记忆。
- 原因：记忆流 → 最终记忆可随时重算，但最终记忆 → 记忆流算不回去。增量模式（"当前最终记忆 + 新增"）会产生误差棘轮，故暂不采用。
- 标"废弃"的内容是已被推翻的旧结论，**一律不纳入**最终记忆。
- 按【来源】判断份量：`【对方确认】` → 已确定；`【我方·未审定】` → 我方判断，不写成已确定；`【原话】` 尽量逐字保留。

最终记忆输出结构：当前状态 / 已确定 / 待确认 / 我方判断 / 原话 / 下一步 / 冲突处理 / 最终记忆正文。

## 三流分拣（记忆流筛选）

界面右侧记忆流可按三条流筛选：

- **当前 · 待确认**（current）：待确认
- **已确认 · 原话**（confirmed）：定、原话
- **判断**（judgment）：判断

废弃单独成流，仅在"全部"下可见，不污染日常筛选。

## 与提示词的关系

四个录入提示词与"从记忆流生成最终记忆"提示词都落地了本规范，见 [提示词模板](prompts.md) 与 `data/demo-prompts.json`。输出端早已定好词表（已确定 / 待确认 / 我方判断），v1 做的是让输入端对齐输出端。
